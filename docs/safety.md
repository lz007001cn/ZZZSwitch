# 安全模型

## 不变量

- 原始差异包永远只读使用。
- 软件内 ZIP 导入只接受当前游戏版本的三服统一目录；先在同卷临时目录解压并按内置切换清单校验，全部通过后才以目录移动替换现有版本，失败时恢复原目录。ZIP 路径穿越、符号链接、重复路径、错误版本和异常解压规模均会在提交前拒绝。
- 软件本体内嵌的 B服渠道组件只写入匹配游戏版本的 `.zzzswitch\packages\<版本>\bilibili`；按用户选择的简化升级策略，B服 profile 启用 `reuseOverlayAcrossGameVersions`，后续有效游戏版本默认复用原归档及组件 SHA-256 清单，使用当前版本的独立目标目录和安装标记。关闭此策略时仍可使用 `overlayCompatibleGameVersions` 明确指定兼容版本。先在同卷临时目录解压并逐文件校验长度与 SHA-256，全部通过后才原子替换。已有组件使用包标识和文件属性进行启动快速校验；切换预检仍会按清单校验 SHA-256，发现缺失或损坏时会执行完整修复并重新预检。
- 测试不访问真实游戏目录。
- `%LOCALAPPDATA%\ZZZSwitch` 只保留配置、状态、路径偏好、进程锁和事务日志；大体积应用数据默认写入当前游戏同卷的 `.zzzswitch\app-data`。
- 事务备份、在线下载工作区、按服快照、Sophon Manifest、Blocks 清单与操作日志分别位于 `.zzzswitch\app-data\backup-records`、`downloads`、`snapshots`、`sophon-manifests`、`blocks-manifests` 和 `operation-logs`。
- 旧版 AppData 数据只在没有未完成事务时迁移；先复制到 `.zzzswitch` 同卷暂存目录并逐文件校验 SHA-256，原子提交新数据根和配置后才删除 C 盘旧副本。
- 实际 Blocks 仓库默认写入游戏同卷的 `.zzzswitch\blocks-cache`，也可迁移到用户指定目录。只读离线包始终位于 `.zzzswitch\packages`；默认只有内置 B 服叠加包，用户主动导入统一离线包时才会出现 `global` / `cn_official`。
- 自定义缓存目录不得位于游戏目录内、磁盘根目录或与 `.zzzswitch` 存储目录重叠；迁移先复制并校验，设置提交后才删除旧位置。
- 默认备份目录是 `.zzzswitch\app-data\backup-records`，每个操作的记录和正文都在其独立目录中。用户另选的自定义备份目录必须为空，不得与游戏目录、`.zzzswitch`、应用配置目录、磁盘根目录或当前备份目录重叠；迁移逐文件校验 SHA-256，设置原子提交后才尝试删除旧位置。
- 切换预检按实际位置检查空间：暂存计入游戏盘，备份计入配置的备份盘；同盘合并需求，异盘分别检查。
- 旧版 `.zzzswitch\data` / `.zzzswitch\cache` 在无未完成事务且新旧目录不冲突时，通过同卷原子目录移动升级为 `app-data` / `blocks-cache`；内部目录同时改为上述明确名称，并修复状态、快照、备份和 Blocks 清单中的旧绝对路径。新旧目录同时包含内容时停止，不猜测合并。
- B服映射到国服资源缓存，不允许建立第三套大体积 Blocks 仓库。
- 旧版仅按服务器和版本保存的 Blocks 清单，只有在内部 `gamePath` 与当前安装完全匹配时才会迁移；其他安装不能认领。
- 原始“热更新存储链接”目录只读使用，不创建硬链接，也不回写原资源包。
- 未通过预检或未经界面确认时不执行真实切换。
- 应用使用会话内命名互斥锁和用户数据目录文件句柄锁阻止重复启动；锁的有效性由 Windows 打开的文件句柄决定，进程异常退出后会自动释放。
- 所有界面写入口共用 `%LOCALAPPDATA%\ZZZSwitch\operation.lock`，防止不同协调器或进程并发修改游戏、缓存、备份和状态。
- 游戏进程或更新进程运行时禁止切换；启动器后台进程会提示，并通过逐文件独占打开检查实际占用。
- 游戏或差异包清单缺少完整性数据、源文件长度或 SHA-256 不符、版本不符、磁盘不足或路径非法时停止。`expectedReplaceCount` / `expectedDeleteCount` 仅作为旧清单兼容字段，实际数量由文件列表计算。
- 在线差异包的就绪查询和切换计划只检查目录身份、文件存在、长度及清单字段格式；实际执行先把确实需要变化的文件复制到同卷暂存区，并在任何游戏文件或 Blocks 被修改前按 Manifest 校验源文件及暂存副本 SHA-256。内置 B 服覆盖层仍在计划阶段完整校验，以便损坏时自动修复。
- 缓存快照只收集指定目录的一级 `version` / `revision` 文件；快照按相对路径和长度判断是否可用，复制过程验证源与目标一致。
- Blocks 初始化和切换要求相关进程全部退出、目录不为空且不存在 `.tmp`；这里只交换 `Persistent\Blocks` 热更新覆盖层，`StreamingAssets\Blocks` 基础资源始终留在游戏目录。缓存清单记录文件数量和总大小；每次切走当前服前都会重新生成活动 Blocks 清单，因此初始化后的新增热更新会自动保存；不同游戏版本不会复用清单。

## 回滚规则

- 自动回滚及手动恢复必须读到与事务/备份一致的 `version_info`；缺失、无效或跨版本时保留事务和副本，不向新版客户端恢复旧文件。已提交事务的收尾仅清理其自身记录。
- 手动恢复独立使用 `RestoreStaging` / `RestorePrepared` / `RestoreApplied` / `RestoreRolledBack` 阶段：先验证全部输入、容量、占用和路径，暂存恢复文件并保存带 SHA-256 的恢复前副本，然后落位并校验；状态准确提交后才更新原备份记录并清理。异常或进程中断时从副本撤销；撤销失败保留副本和日志供重试。最后阶段仅用于已完成操作的收尾，不再依赖已清理的副本。
- 未完成普通文件、手动恢复或 Blocks 事务存在时禁止其他写操作、备份删除与轮换；检查入口允许只读检测和重试恢复。重置识别仅清除检测缓存，保留路径、备份关联及事务，不能绕过待恢复状态。
- 切换计划保存关键文件及受影响文件的属性，在执行和备份后再次复核版本/属性；不增加完整文件哈希。属性完全未变的静默篡改仍由原有执行完整性校验覆盖其原有范围。
- 在线包发现来源长度/哈希错误后写入无效标记并立即移出就绪集合，重新生成或完整验证成功才清除。结构异常的动态清单按包隔离，不能让整个包列表崩溃。

- 原本存在的受影响文件复制到当前备份根目录的 `<operation>\files`；`backup.json` 不保存正文哈希，复制过程验证源和目标一致。
- 原本不存在、切换新增的目标记入 `originallyMissingFiles`，回滚时删除。
- 切换删除的文件也在操作前备份，回滚时恢复。
- 目标服缓存快照将覆盖的文件同样加入本次事务备份；缓存恢复失败会回滚差异文件和缓存文件。
- Blocks 目录交换有独立事务记录；跨磁盘时先在目标卷暂存并校验后落位，恢复时优先保留已验证副本。普通文件操作失败时先恢复 Blocks，再恢复差异文件备份。
- 普通文件另有持久化事务记录；进程被强制结束后，下次启动会联合恢复 Blocks 与普通文件。
- 执行时先根据目标 Manifest 检查当前游戏文件；内容已经满足目标值的替换项、已满足的 INI 项和不存在的可选删除项不进入本次暂存、备份和执行集合。写入首个暂存文件前，现有事务日志先记录 `Staging`；随后流式复制到游戏同卷的 `.zzzswitch\staging\<operation>` 并同时计算源 SHA-256，再校验暂存副本。只有暂存完整成功、来源快照和实际受影响文件的备份完成且日志推进至 `Prepared` 后，才允许修改游戏文件或 Blocks。落位时使用同卷移动。
- `Staging` 阶段中断时，启动恢复只清理该事务明确对应的暂存目录，不执行游戏文件回滚；目录被占用或存在冲突事务时保留日志供重试，未完成备份保留供检查。无日志的历史暂存目录不自动认领或批量清理。
- `backup.json` 记录操作结果和回滚结果。
- 新备份始终使用操作目录下的实体文件树。短期测试版生成的 `backup-content\sha256` 对象仅为已有备份保留兼容读取，不再新增、迁移或自动回收。
- 成功切换后每份游戏安装按来源服各保留一份最新可恢复备份；国服、国际服、B服最多三个槽位，同来源服新备份在事务完全提交后替代旧备份。完整回滚的失败记录、启动时已完整恢复的中断记录与被替代的成功记录自动清理，不完整或损坏记录保留供人工排查。

## 有意限制

- 不对整个游戏目录做全量哈希。
- 客户端内置识别特征绑定游戏版本。其他版本使用同版本的国服/国际服 Sophon Manifest 校验关键文件长度与 MD5；首次无已确认结果时完整识别，普通旧状态不能代替识别。正常启动和切换前复用 `state.json` 中的 `clientDetection`，只核对游戏路径、版本、关键文件（含缺失项）与 INI 的长度/修改时间/创建时间、识别配置、Manifest 文件属性和操作记录。变化、未知/混合状态、损坏记录、失败操作或未完成事务触发完整识别；显式只读检查始终完整识别且不保存缓存。此属性复用不检测保留全部属性的静默内容篡改，不能替代切换执行中的来源与暂存完整性校验。
- 已确认来源服的切换成功后，目标文件通过现有执行校验，才将目标服与新的属性记录一起提交到状态文件；不再立即重复识别。失败/恢复后重新识别。缓存保存失败不影响检测结果；损坏的状态原文不由检测流程覆盖。首次缺少识别清单时尝试获取一次，失败可从差异包管理手动重试；明确的只读检查不下载清单。
- 游戏升级后保留旧版本差异包、缓存和备份，但不把它们当作新版数据。读取到当前游戏版本与备份版本不同时拒绝普通备份恢复。B服继续使用同版本国服 Manifest 核心特征加现有组件 SHA-256 识别，组件损坏或核心不一致时不得误认成国服。CN/B服切换只复用覆盖层操作，跨区域方向必须组合当前版本在线基础差异，不能重用旧核心。默认复用不代表已核验每个未来版本的官方 SDK；此次策略不提供 SDK 自动下载。
- 正常检查可靠识别为 B服后，若 `config.ini` 中 `[General] game_version` 与 `version_info` 的实际版本不同，在操作锁内且无相关进程、无未完成事务时只同步这一项。采用同目录临时文件与原子替换，最近一次修改前的完整 INI 保存在 `config.ini.zzzswitch-version.bak`；重复检查不重复写入。显式只读检查不执行此同步。切换到 B服时也将当前版本并入原有渠道 INI 事务补丁，由既有事务备份负责回滚。其他配置项保留，不整份覆盖旧 INI。
- 不尝试识别账号或登录状态。
- 不处理启动器修复、更新并发或注册表配置。
- 不提供强制来源服覆盖；来源服为未知/混合时停止，由用户先核查差异文件。
- WPF 程序以当前用户身份运行，不自动请求管理员权限。
- `.lock` 文件本身可以在退出后保留；它不是“正在运行”的依据，不应靠删除文件解除锁定。

## 2026-09-13 复审补强

- 状态损坏且存在待恢复事务时停止恢复；普通文件与 Blocks 的安装、版本、方向及提交依据冲突时保留两份日志，不猜测提交结果。
- 普通文件预检、执行前、备份后和回滚输入检查拒绝目标、来源、备份及快照文件路径中的重解析点；父目录属性仅在当前检查阶段去重，后续阶段重新检查。备份记录与临时文件写入、备份删除同样受保护。这不构成对恶意并发更换路径的句柄级防护。
- 内置特征与 Manifest 识别分支均拒绝损坏的 B 服覆盖层；仅相关内置识别缓存更新模式版本。
- 反向差异包完整生成后清除失效标记；失效包允许主动完整验证，验证成功才恢复就绪。固定配置和动态包均隔离非法路径。
- 上述检查不新增正常启动/切换的全量扫描、哈希或大文件副本；完整包验证由用户主动触发。

## 1.3.7 发布前备份修复

- 更改备份目录时按旧根目录的相对路径同步 state.json 的 LastBackupPath，保留原操作、安装和版本身份，不按时间另选记录。状态保存完成后才删除旧副本；新位置启用后状态保存失败则保留两份副本并显示警告。损坏状态在迁移前拒绝。
- 最后备份损坏或路径关联失效时返回不可恢复结果；恢复按钮完整捕获异常，不允许 JSON 或路径异常逃出界面事件。
- 两种手动恢复入口共用忙碌状态、恢复执行和结果呈现；执行期间禁止关闭备份窗口，释放操作锁后复检，最后复位主界面。恢复提交但收尾未完成必须显示警告与重试指导。
