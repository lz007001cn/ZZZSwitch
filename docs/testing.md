# 测试说明

测试项目不使用 NuGet 测试框架，避免引入第三方依赖。它是一个返回标准退出码的 .NET 8 控制台程序。

运行：

```powershell
dotnet run --project tests\ZZZSwitch.Core.Tests\ZZZSwitch.Core.Tests.csproj -c Release
```

所有 fixture 位于 `%TEMP%\ZZZSwitch.Tests\<guid>`，测试结束后递归删除自己的 GUID 子目录。测试从不使用配置中的真实 `E:` 游戏路径。

当前覆盖 81 项：三服识别与 B服/国服资源归一；路径安全；游戏目录、版本、差异包数量、逐文件长度和 SHA-256；进程、占用和删除预检；缓存快照过滤、字段校验与损坏拒绝；Blocks 初始化、同卷交换、跨磁盘校验复制、各中断阶段恢复及联合回滚；多游戏安装的清单隔离与旧清单安全迁移；自定义缓存迁移和旧版本清理；自定义备份目录的校验迁移、设置持久化和危险路径拒绝；普通文件持久化事务恢复；备份 SHA-256、每安装按来源服三个槽位轮换、不完整备份清理、损坏记录隔离与最后切换精确恢复；配置损坏、字段无效及重复切换方向容错；关键 JSON 原子写入；损坏状态文件容错；成功与失败计数；新增、替换和删除文件回滚；进程内、跨协调器和应用生命周期互斥；旧备份恢复策略；统一 `.zzzswitch` 存储布局与目录修复。

WPF UI 冒烟测试还验证：正式版三服入口；`MainWindowViewModel` 绑定和忙碌状态传播；三服 Command 路由、忙碌禁用、重复执行保护及同步/异步异常转交；复用服务器卡片属性；扫描展示格式化器和独立摘要控件；默认宽度与最窄窗口在扫描前后宽高不变；125%、150%、200% 布局缩放压力；缓存与备份位置窗口；“恢复上次状态”位于备份历史而非主界面；同服切换在规划前短路、忙碌状态在扫描前短路、无效扫描报告阻止缓存管理、备份目录打开动作使用当前配置路径。

启动 UI 编排测试使用纯委托和临时路径验证：恢复结果与状态警告完整传递；备份轮换使用 `state.json` 中精确的最后备份保护路径；轮换异常不会中断启动；零个/单个游戏目录候选无需打开交互选择窗口。

`ZZZSwitch.Ui.Smoke` 在 STA 线程中实例化 WPF 资源和窗口但不显示窗口、不触发 `App.OnStartup`、不读取游戏目录；它检查正式版三服按钮、版本号以及缓存管理操作状态。

故障场景通过 `IFileOperations` 包装器精确注入一次复制或删除失败，随后让正常文件操作完成回滚，能够验证真实恢复结果而不是只验证返回值。
